## Challenges

1. **Code review discovering issues mà tests miss**
   - **Story 2.2:** 5 patch items — Memory safety (use-after-free, buffer UB), platform guard bugs, unsafe code placement
   - **Story 2.4:** 12 patch items — Logic bugs (margin storage, enum conversion, mutex poisoning, is_default flag)
   - **Story 2.5:** AC compliance gap — Native HTML instead of @sapo/ui-components required Story 2.5.1 follow-up

2. **AC reading comprehension (Story 2.5)** — AC-1 explicit yêu cầu @sapo/ui-components, nhưng implementation ban đầu dùng native HTML. Code review catch được, spawn Story 2.5.1 để fix. Mất ~0.5 ngày rework.

3. **Platform-specific unsafe code complexity (Story 2.2)** — Win32 `PWSTR` lifetime management, buffer handling UB không intuitive với Rust developers. Requires deep expertise hoặc careful review.

4. **Test blindspot** — Tests viết với cùng mindset sai như implementation code. Tests pass nhưng không verify đúng behavior. Edge cases missed.

---

## Key Lessons

1. **Code review is critical defense layer** — Tests không catch được: memory safety issues, AC compliance gaps, logic edge cases. Code review phải mandatory trước merge.

2. **Team learns incrementally** — Stories 2.1-2.5 có nhiều patch rounds. Story 2.6 clean. Visible improvement across epic.

3. **Unsafe code needs protocol** — Win32/CUPS unsafe blocks cần peer review focused on lifetime/memory safety. Cannot rely on tests alone.

4. **AC verification must be pre-merge** — Story không được mark "done" until ALL ACs verified line-by-line. Prevents rework và wasted effort.

5. **Platform abstraction pattern proven** — Trait-based approach (`PrinterManager`, `SecretManager`) scales well. Conditional compilation với `#[cfg]` guards effective.
