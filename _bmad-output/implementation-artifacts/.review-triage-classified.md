## DECISION_NEEDED (requires user input)

**DN-1: Hardcoded defaults overwrite config** (FINDING-2)
- **Issue**: `save()` always writes hardcoded values (A4, 0mm margins, RGB) instead of reading from Printer aggregate
- **Question**: Does the Printer aggregate currently expose methods like `printer.paper_size()`, `printer.margins()`, `printer.color_mode()`? Or should we defer config persistence to Story 2.5/2.6?
- **Evidence**: Spec says "Store margins in mm (domain units)" but code hardcodes `0, 0, 0, 0`. AC-2 says "Convert enums to TEXT" implying they should be read from aggregate.
- **Location**: printer_repository.rs:66-84
- **Source**: blind+edge+auditor

**DN-2: device_id vs PrinterId confusion** (FINDING-5)
- **Issue**: Code uses `printer.id().to_string()` for device_id field. Spec says "DO NOT store PrinterId — use device_id as stable key"
- **Question**: Does Printer aggregate have a separate `.device_id()` method? Or should device_id come from Windows/CUPS backend (Stories 2.2/2.3)?
- **Evidence**: AC-2 says use device_id for UPSERT; Dev Notes explicitly warn against storing PrinterId
- **Location**: printer_repository.rs:33
- **Source**: blind+edge+auditor
